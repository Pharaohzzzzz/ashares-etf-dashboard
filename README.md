# ETF资金雷达

本地运行的 A 股 ETF 每日监测网站，监测 14 只宽基、科技、金融、医药通信和港股科技 ETF。

访问地址：http://127.0.0.1:37821

## 一键使用

双击 `启动ETF资金雷达.cmd`。脚本会：

1. 检查本地服务是否已经运行。
2. 必要时在后台启动 Node.js 服务。
3. 在默认浏览器中打开监测网站。

命令行启动：

```powershell
npm start
```

后台启动：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-dashboard.ps1
```

停止后台服务：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\stop-dashboard.ps1
```

## 自动更新

- 交易日 09:30-11:30、13:00-15:00，每 30 秒刷新报价和分时数据。
- 同一轮刷新同步交易所 IOPV，并用东方财富公开报价字段做来源校验或明确标注的降级补充。
- 交易日 15:30 更新收盘快照。
- 交易日 18:00 再同步日线和份额快照。
- 服务启动时检查并补齐缺失的历史日线。
- 服务首次启动时从交易所自动回填最近 251 个可取得交易日的官方份额，用于生成完整的 250 日变化曲线。
- 之后每日只请求尚未完成的新交易日；已完成日期写入 SQLite 同步状态表，重复执行不会重复请求或产生重复记录。
- 单日交易所接口失败不会覆盖已有数据，也不会阻止另一交易所成功入库；失败日期下次启动或每日更新时重试。
- 电脑关机期间网站无法运行；下次启动时会补抓缺失交易日的日线。
- 页面打开后每 30 秒读取一次本地服务数据。

## 指标口径

- 20日量比：当前成交额 ÷ 前 20 个完整交易日成交额均值。
- 近5日/20日涨跌：当前价格相对第 5/第 20 个交易日前的收盘价。
- 份额变化：当前总份额 − 上一已记录交易日总份额。
- 估算净申赎：份额变化 × 当前价格参考值。
- 累计估算净申赎：指定区间内逐日“官方份额变化 × 当日收盘价”的累计值，支持 20/60/250 日视角。
- 连续净申购/净赎回：按相邻官方份额记录计算当前连续同向变化天数。
- 份额历史分位：当前官方份额在所选历史窗口中的包含式百分位，100% 表示窗口内最高。
- 成交额分位：当前成交额在自身近 250 个交易日成交额中的百分位。
- 尾盘成交占比：14:30-15:00 成交额 ÷ 当日成交额。
- IOPV：交易所计算的基金份额参考净值，随成分证券价格变化；本网站优先使用上交所、深交所实时 IOPV 字段。
- 折溢价率：`市场价 ÷ IOPV − 1`。正值为溢价，负值为折价；不使用“IOPV ÷ 市场价”或其他平台的相反口径。
- 当日折溢价统计：开盘、最高、最低、均值和最新值只使用同一交易日内已实际记录的市场价与 IOPV 配对样本。上市首日、接口中断或本地首次启动造成的样本缺口保留为空，不按前值填充。
- 收盘折溢价历史分位：每个交易日取最后一个有效 IOPV 与同一来源市场价计算折溢价，再与已积累的历史交易日比较。不足 5 个有效收盘样本时显示样本不足，不伪造 250 日历史。
- 异常资金评分：0–100 分，由 20 日成交额量比（35%）、官方份额变化历史分位（30%）、连续净申购/净赎回（15%）、宽基或同分类共振（20%）组成。40–59 为观察，60–79 为活跃异动，80–100 为高强度异动。
- 历史回测：信号在交易日收盘后生成，参数版本 `signal-score-v2.0.0` 默认在下一可交易日开盘入场，自入场日起持有 1/3/5/10 个交易日后收盘退出。评分只使用信号日及以前的数据，`signalAvailableAt` 记录为信号日 15:00（Asia/Shanghai）。
- 回测成本：同时计算零成本和基准成本。基准成本默认佣金 0.03%、滑点 0.05%、冲击成本 0.02%，即单边合计 0.10%，买卖两侧均计入；所有基准收益使用与信号相同的次日开盘入场、N 日收盘退出和成本规则。
- 最大回撤：从次日开盘有效入场价起算，使用持有期内后续交易日最低价，命名为“入场后盘中低点回撤”；不再使用低估的收盘价回撤。
- 训练/验证：按可评分交易日的全池时间顺序切分前 70% 训练、后 30% 留出验证；分别评估未来收益、回撤、最大有利波动、同期等权基准、命中率、同 ETF 无条件命中率、相对提升与样本数。

ETF 二级市场买入不增加基金总份额。份额变化只能作为一级市场净申赎代理，不能确认交易账户身份。

详情页的累计净申赎使用收盘价估算，并非基金公司确认的一级市场现金申赎金额。上市时间不足、交易所尚未发布或官方接口未返回的日期会显示为缺口，不填零、不回填模拟值。

## 信号评分与回测

首页和详情页展示固定参数 `signal-score-v1.0.1` 的分项实际值、历史分位、权重和贡献分。评分只读取信号日及以前的数据；未来价格只用于事后评价，不回流到信号日评分。

“信号评估”页面提供：

- 训练期和留出验证期分别展示的样本数、命中率与相对提升。
- 按 1/3/5/10 日和 ETF 分类的区分度热力图。
- 分 ETF 的样本数、命中率、无条件命中率、平均/中位收益、最大回撤和最大有利波动。
- 信号时间线及单事件评分贡献、未来价格路径、同期基准和旧版规则对照。
- 日期范围、ETF、分类、评分等级、数据切分和预测周期筛选。

命中的定义是 ETF 未来收益高于监测池同期等权收益。相对提升是信号命中率减去同 ETF、同数据切分的无条件命中率，不是收益率承诺。官方份额缺失或不足的日期直接排除，不插值、不填零。尾盘成交占比仍是当日辅助标签，不进入长期回测评分。

回测运行写入 SQLite 的 `backtest_runs` 和 `signal_events` 表。参数版本与历史数据指纹相同的重复运行直接复用已有结果，不重复写入事件；旧版 `daily_metrics.signals_json` 继续保留作为对照。

生产界面使用“异常放量+份额变化候选”“一级市场申购异动”等中性名称。它们只是公开数据的异常提示，不是国家队身份确认，也不构成投资建议。历史规则对照区保留“旧版护盘候选”字样，仅用于说明旧行为代理。

## 数据源

- 东方财富公开行情、分时、日线和份额字段。
- 上交所实时行情快照：`yunhq.sse.com.cn` 的 IOPV 字段，覆盖上交所 ETF。
- 深交所基金行情：`fund.szse.cn` 的 `netValue` 与 `piciopv` 字段，覆盖深交所 ETF；同时用于补齐当日逐分钟 IOPV。
- 上交所、深交所官方 ETF 历史份额。上交所按交易日读取全市场 ETF 份额；深交所按官方日期范围接口分段读取。
- 东方财富 ETF 列表 `f441` IOPV 字段仅作为补充校验和降级来源。使用时页面和 CSV 会明确标注“东方财富（补充）”。
- 上交所、深交所、巨潮资讯和中央汇金官网作为官方核验入口。

公开接口可能调整或短时不可用。网站会保留上一次有效数据、标记“数据过期”并记录错误。官方值与补充值的发布时间相差超过 90 秒时视为无法对齐，只保留官方值用于计算，不强行合并；在 90 秒内且 IOPV 相对偏差超过 0.1% 时标记“来源冲突”，当前折溢价显示“数据异常”。IOPV 缺失、为 0、为负、时间未来或价格无效时同样不计算折溢价。

交易所官方 IOPV 与市场价可能以不同精度发布，本站仍按原始字段计算，不做净值推算。东方财富补充源与其自身原始字段对照时，应使用相同发布时间的市场价和 IOPV；跨分钟价格不能拼接成一个折溢价点。

## 首次安装

需要 Node.js 24 或更高版本。

```powershell
npm install
npm test
npm start
```

首次启动会为 14 只 ETF 补齐约两年的日线数据，并回填官方份额历史。实际耗时取决于交易所接口响应速度；页面在回填期间仍可访问，完成后详情页自动读取新增数据。

## 验证

```powershell
npm test
npm audit --omit=dev --audit-level=moderate
```

运行数据保存在 `data/dashboard.db`。删除数据库会清空本地快照，但服务重启后会重新补齐日线，并重新回填最近 251 个可取得交易日的官方份额。

常用接口：

- `GET /api/summary`：14 只 ETF 总览，同时包含当前 IOPV、市场价、折溢价率、来源、数据时间和异常状态。
- `GET /api/etfs/:code`：行情、日 K、默认 250 日官方份额分析及 IOPV/折溢价分析。
- `GET /api/etfs/:code/share-history?days=20|60|250`：指定视角的官方份额、累计净申赎、覆盖率与缺失日期。
- `GET /api/etfs/:code/iopv-history?days=1..250`：当日 IOPV 配对样本、折溢价统计、收盘历史、历史分位、覆盖率与来源。
- `GET /api/export.csv`：ETF 总览 CSV，包含折溢价率、IOPV 来源与数据时间。
- `GET /api/export.csv?code=510300&type=shares`：指定 ETF 的 250 日官方份额 CSV。
- `GET /api/export.csv?code=510300&type=iopv`：指定 ETF 的收盘 IOPV、市场价、折溢价率与来源 CSV。
- `GET /api/backtests/summary`：最新固定参数回测、训练/验证汇总、分类与分 ETF 结果、数据状态。
- `GET /api/backtests/events?split=validation&horizon=5&code=510300`：按切分、周期、ETF、分类、等级和日期筛选信号事件。
- `GET /api/backtests/events/:id`：单次信号的贡献分、未来路径和旧规则对照。
- `GET /api/export.csv?type=backtest&split=validation&horizon=5`：导出回测明细 CSV。

## 已知限制

- 交易所接口可能调整字段、限流或短时不可用；网站保留最近一次成功数据，并按日期重试失败请求。
- “可取得交易日”以交易所实际返回为准。晚于窗口起点上市或官方数据缺失的 ETF 会显示较少的可用天数，不做伪造补齐。
- 官方份额通常为上一交易日口径；盘中可能只有行情快照份额，详情页会分别标注官方截止日期和来源。
- 上交所实时快照当前可直接取得最新 IOPV；若本地服务在盘后才首次启动，上交所当日逐分钟 IOPV 无法从该接口回溯，当日统计只覆盖实际记录时点。深交所接口可返回当日逐分钟 IOPV，但仍过滤收盘后的 0 值。
- 折溢价历史从本站成功写入首个有效交易日开始积累。旧数据库没有历史 IOPV，不能从收盘价或基金单位净值倒推成 IOPV；因此初次使用时分位和历史趋势可能显示样本不足。
- 港股、跨境等 ETF 的 IOPV 受海外市场时差、汇率和估值日影响，折溢价不等同于可立即执行的套利收益。
- 首版评分使用固定参数，训练期结果可供后续校准参考，但当前不会每日自动调参或改写参数版本。
- 未来 10 日结果在最近交易日尚未形成时显示“数据不足”，不会用 0 或部分路径冒充完整结果。
