# ETF资金雷达

本地运行的 A 股 ETF 每日监测网站，默认初始化宽基、科技、金融、医药通信和港股科技 ETF，并可在页面内增删监控标的。

访问地址：http://127.0.0.1:37821

## 一键使用

双击 `启动ETF资金雷达.cmd`。脚本会：

1. 检查本地服务是否已经运行。
2. 必要时在后台启动 Node.js 服务。
3. 在默认浏览器中打开监测网站。

命令行启动：

```powershell
npm start
```

后台启动：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-dashboard.ps1
```

停止后台服务：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\stop-dashboard.ps1
```

## 自动更新

- 交易日 09:30-11:30、13:00-15:00，每 30 秒尝试刷新报价和 IOPV。详情的东方财富分时数据在打开抽屉时单独读取。
- 交易日判断来自深交所官方交易日历接口，并持久化到本地 `trading_calendar` 表。周末、国庆、春节、普通节假日及上下午休市均按官方 `jybz` 标记执行；接口失败时保留缓存并标记“交易日历可能过期”，无缓存时暂停自动更新。
- IOPV 优先取交易所数据，东方财富报价字段用作来源校验或标注的降级补充。盘中超过 3 分钟未更新时隐藏当前折溢价。
- 交易日 15:30 更新收盘快照。
- 交易日 18:00 再同步日线和交易所官方份额。盘后任务按交易日记录完成状态，程序错过执行时点后会在后续检查中补跑。
- 服务启动时比较最新报价、日线、官方份额和 IOPV 日期；报价领先日线时补日线，份额日期落后或中间缺口时补官方份额，IOPV 落后时刷新。只有日线数量达到 250 根不再被视为“已补齐”。
- 任务状态持久化在 `sync_tasks`，记录状态、最后成功日期、失败日期、目标日期和重试次数。服务错过 15:30、18:00 或关机数日后重启，会按日期差异继续补跑。
- 服务首次启动时从交易所自动回填最近 251 个可取得交易日的官方份额，用于生成完整的 250 日变化曲线。
- 之后每日只请求尚未完成的新交易日；已完成日期写入 SQLite 同步状态表，重复执行不会重复请求或产生重复记录。
- 交易所份额失败批次保留已有数据，并按 30/60 分钟节奏重试可补缺口。无需同步的交易所和可确认的上市前区间排除在完整性统计之外。
- 电脑关机期间网站无法运行；下次启动时会补抓缺失交易日的日线。
- 页面打开后每 30 秒读取一次本地服务数据。

## 指标口径

- 20日量比使用当前成交额除以前 20 个完整交易日的成交额均值，样本少于 20 个时留空。
- 近5日/20日涨跌：当前价格相对第 5/第 20 个交易日前的收盘价。
- 份额变化：仅在当前行情交易日已有交易所官方份额，且前一实际交易日官方份额完整时，计算“当前官方总份额 − 前一官方总份额”。
- 估算净申赎为相邻交易日的官方份额变化乘同一交易日的不复权收盘价。缺少同日价格时保留可用份额变化，估算留空。日 K 继续使用前复权口径。
- 累计估算净申赎按完整交易日逐日累加，支持 20/60/250 日视角。详情分别标注官方记录、连续份额变化及有效估算的覆盖；完整区间累计值在缺数据时留空。旧库的不复权收盘价由日线同步补齐。
- 连续净申购/净赎回：按相邻官方份额记录计算最近官方日的连续同向变化天数。
- 份额历史分位：当前官方份额在所选历史窗口中的包含式百分位，100% 表示窗口内最高。
- 成交额分位：当前成交额在自身近 250 个交易日成交额中的百分位。
- 尾盘成交占比：14:30-15:00 成交额 ÷ 当日成交额。
- IOPV：交易所计算的基金份额参考净值，随成分证券价格变化；本网站优先使用上交所、深交所实时 IOPV 字段。
- 折溢价率：`市场价 ÷ IOPV − 1`。正值为溢价，负值为折价；不使用“IOPV ÷ 市场价”或其他平台的相反口径。
- 当日折溢价统计：开盘、最高、最低、均值和最新值只使用同一交易日内已实际记录的市场价与 IOPV 配对样本。上市首日、接口中断或本地首次启动造成的样本缺口保留为空，不按前值填充。
- 收盘折溢价历史分位：每个交易日取最后一个有效 IOPV 与同一来源市场价计算折溢价，再与已积累的历史交易日比较。不足 5 个有效收盘样本时显示样本不足，不伪造 250 日历史。
- 异常资金评分：0–100 分，由 20 日成交额量比（35%）、官方份额变化历史分位（30%）、连续净申购/净赎回（15%）、宽基或同分类共振（20%）组成。40–59 为观察，60–79 为活跃异动，80–100 为高强度异动。

行情快照中的份额字段仅用于展示和校验，不参与官方份额变化、估算净申赎或份额信号。当前行情交易日官方份额尚未发布时，`shareDelta` 与 `estimatedSubscription` 返回 `null`，`shareMetricStatus` 为 `pending`；页面显示“待官方发布”。最近完整官方日的份额变化通过 `latestOfficial*` 字段单独返回，并明确标注日期，不视为今日实时净申赎。

ETF 二级市场买入不增加基金总份额。份额变化只能作为一级市场净申赎代理，不能确认交易账户身份或国家队身份。

详情页的累计净申赎使用收盘价估算，并非基金公司确认的一级市场现金申赎金额。上市时间不足、交易所尚未发布或官方接口未返回的日期会显示为缺口，不填零、不回填模拟值。

页面“运行记录”下方展示各类数据的来源、日期、缺口、任务结果和交易日历缓存。可以按数据类型补抓。`GET /api/summary` 的 `dataStatus` 字段提供同一信息。休市时首页提供最近交易日摘要，汇总和异动卡片分别使用标注的日期。

## 信号评分

首页和详情页使用固定参数 `signal-score-v2.1.0`。份额变化的并列分位使用平均名次，持平项计零分，共振至少需要两只 ETF 达到放量阈值。评分只读取信号日及以前的数据。首页异动卡片按同一评分日的分数排列，详情保留分项实际值、历史分位、权重和贡献分。

生产界面使用“异常放量+份额变化候选”“一级市场申购异动”等中性名称。它们只是公开数据的异常提示，不是国家队身份确认，也不构成投资建议。首页与详情页不再提供历史回测、训练验证或信号评估入口。

## 数据源

- 东方财富公开行情、分时、日线和份额字段。
- 上交所实时行情快照：`yunhq.sse.com.cn` 的 IOPV 字段，覆盖上交所 ETF。
- 深交所基金行情：`fund.szse.cn` 的 `netValue` 与 `piciopv` 字段，覆盖深交所 ETF；同时用于补齐当日逐分钟 IOPV。
- 上交所、深交所官方 ETF 历史份额。上交所按交易日读取全市场 ETF 份额；深交所按官方日期范围接口分段读取。
- 东方财富 ETF 列表 `f441` IOPV 字段仅作为补充校验和降级来源。使用时页面和 CSV 会明确标注“东方财富（补充）”。
- 上交所、深交所、巨潮资讯和中央汇金官网作为官方核验入口。

公开接口可能调整或短时不可用。网站会保留上一次有效数据、标记“数据过期”并记录错误。官方值与补充值的发布时间相差超过 90 秒时视为无法对齐，只保留官方值用于计算，不强行合并；在 90 秒内且 IOPV 相对偏差超过 0.1% 时标记“来源冲突”，当前折溢价显示“数据异常”。IOPV 缺失、为 0、为负、时间未来或价格无效时同样不计算折溢价。

交易所官方 IOPV 与市场价可能以不同精度发布，本站仍按原始字段计算，不做净值推算。东方财富补充源与其自身原始字段对照时，应使用相同发布时间的市场价和 IOPV；跨分钟价格不能拼接成一个折溢价点。

## API 校验、错误码与 CSV provenance

- ETF 代码和 CSV `type` 均做白名单校验；份额与 IOPV 历史视角只接受页面提供的固定天数。非法输入返回 HTTP 400。
- API 错误统一为 `{"error":{"code":"STABLE_CODE","message":"可读说明"}}`。服务内部异常固定返回 `INTERNAL_ERROR`，详细堆栈只写服务日志。
- 总览 CSV 与份额 CSV 包含行情时间、行情抓取时间、行情状态、官方份额日期、官方份额来源和官方份额抓取时间。
- 官方份额的 `official_fetched_at` 与行情快照的 `snapshot_fetched_at` 分开保存。行情快照被官方数据拒绝时，不会改写官方值或官方抓取时间。

## 备份、恢复与清理

服务每日自动创建 SQLite 在线备份到 `data/backups/`，保留最近 14 份，并执行 `PRAGMA integrity_check` 和 `PRAGMA foreign_key_check`。备份、清理和 WAL checkpoint 每日至少执行一次。

```powershell
npm run backup
npm run maintain
```

恢复前必须先停止网站：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\stop-dashboard.ps1
npm run restore -- .\data\backups\dashboard-20261120-120000.db
```

恢复脚本确认网站端口未在监听，再校验备份，为当前数据库创建 `before-restore-*.db` 安全备份。预校验通过后在同一目录改名替换，替换失败时原文件仍可用，替换后校验失败时尝试从安全备份回滚。默认清理 90 天以前的盘中行情快照和 30 天以前的更新日志，日线、官方份额、日指标和 IOPV 样本长期保留。

可配置环境变量：`BACKUP_RETENTION`、`SNAPSHOT_RETENTION_DAYS`、`UPDATE_LOG_RETENTION_DAYS`、`LOG_MAX_BYTES`、`LOG_ROTATION_FILES`。服务日志写入 `data/logs/dashboard.log`，默认 5 MB 轮转并保留 5 份。

## 键盘与可访问性

- ETF 表格行和信号卡片支持 Tab 聚焦，Enter 或 Space 打开详情。
- 可排序表头是原生按钮，支持 Enter/Space，并通过 `aria-sort="ascending|descending|none"` 报告排序状态。
- 详情抽屉使用 `role="dialog"`、`aria-modal="true"`；打开时聚焦关闭按钮，Tab/Shift+Tab 限制在抽屉内，Escape 关闭。
- 关闭后焦点恢复到原触发行或触发按钮；若列表已刷新导致原节点替换，则按 ETF 或信号事件标识找到对应新节点。

```powershell
npm install
```


运行数据保存在 `data/dashboard.db`。删除数据库会清空本地快照，但服务重启后会重新补齐日线，并重新回填最近 251 个可取得交易日的官方份额。

常用接口：

- `GET /api/summary`：当前监控 ETF 总览，同时包含行情快照份额、当前官方份额、当前日份额状态、最近官方日指标、5/20 日累计估算净申赎、当前 IOPV、市场价、折溢价率、来源、数据时间和异常状态。
- `GET /api/etfs/manage`：当前监控、已移出标的、排序和 30 只容量状态。管理界面使用 `includeSummary=false` 只取目录。
- `POST /api/refresh`：手动刷新报价、IOPV 和官方份额。`kind=quotes|history|shares|iopv` 可单独处理指定数据类型。
- `GET /api/etfs/lookup?code=510300`：校验 6 位代码、名称、市场与 ETF 类型。
- `POST /api/etfs`、`PATCH /api/etfs/:code`、`DELETE /api/etfs/:code`：新增、编辑、移出监控；移出需要 `confirm=true`，历史数据库保留。
- `PUT /api/etfs/order`、`POST /api/etfs/order/restore`：保存置顶/普通区顺序或恢复默认顺序。
- `GET /api/etfs/:code`：行情、日 K、默认 250 日官方份额分析及 IOPV/折溢价分析。页面的 `compact=1` 省去重复份额区间和收盘折溢价历史，它们可通过各自的历史接口读取。
- `GET /api/etfs/:code/share-history?days=20|60|250`：指定视角的官方份额、累计净申赎、覆盖率与缺失日期。
- `GET /api/etfs/:code/iopv-history?days=1..250`：当日 IOPV 配对样本、折溢价统计、收盘历史、历史分位、覆盖率与来源。
- `GET /api/export.csv`：仅导出当前 enabled ETF，包含折溢价率、IOPV、5/20 日累计估算净申赎、波动率与数据时间。
- `GET /api/export.csv?code=510300&type=shares`：指定 ETF 的 250 日官方份额 CSV。
- `GET /api/export.csv?code=510300&type=iopv`：指定 ETF 的收盘 IOPV、市场价、折溢价率与来源 CSV。

## 已知限制

- 交易所接口可能调整字段、限流或短时不可用；网站保留最近一次成功数据，并按日期重试失败请求。
- “可取得交易日”以交易所实际返回为准。晚于窗口起点上市或官方数据缺失的 ETF 会显示较少的可用天数，不做伪造补齐。
- 交易所官方份额通常不是盘中逐秒数据。当前日官方份额未发布时，行情快照份额仍可展示，但不会与上一官方份额混算；页面会分别标注行情快照、当前官方份额和最近官方日截至日期。
- 上交所实时快照当前可直接取得最新 IOPV；若本地服务在盘后才首次启动，上交所当日逐分钟 IOPV 无法从该接口回溯，当日统计只覆盖实际记录时点。深交所接口可返回当日逐分钟 IOPV，但仍过滤收盘后的 0 值。
- 折溢价历史从本站成功写入首个有效交易日开始积累。旧数据库没有历史 IOPV，不能从收盘价或基金单位净值倒推成 IOPV；因此初次使用时分位和历史趋势可能显示样本不足。
- 港股、跨境等 ETF 的 IOPV 受海外市场时差、汇率和估值日影响，折溢价不等同于可立即执行的套利收益。
- 异常资金评分使用固定参数，不会每日自动调参或改写参数版本。
- 默认清单只在首次目录迁移时初始化置顶与重点标记；之后启动不会重新启用用户已移出的 ETF，也不会覆盖分类、颜色和排序。
