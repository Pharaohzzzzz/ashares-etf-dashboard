# ETF 官方份额长历史实施计划书

**目标**　保留 250 个交易日为详情默认区间，增加约 3 年（750 日）、约 5 年（1250 日）和全部可得的官方总份额与净申赎估算。使用交易所官方日份额及可配对的不复权日收盘。

## 执行步骤

- [x] **后端读取。** 保留 `20|60|250` 历史 API 和短窗评分口径。扩展 `GET /api/etfs/:code/share-history?days=750|1250|all`，只返回指定长窗口，按已上市和可取得历史裁剪，明确 `coverage.requestedDays`、`availableDays`、`shareDeltaDays`、`estimatedDays`、起止日期。详情首次加载仍走短窗。
- [x] **长历史补数。** 以 `POST /api/etfs/:code/share-history?days=750|1250|all` 触发有界后台批次，`GET` 返回 `backfill` 的实际进度。复用官方提供方、SQLite 去重和不复权 K 线。沪市从实测 2012-01-04 起按交易日复用全市场响应，深市从实测 2016-11-23 起按日期区间获取。优先近期，避免反复请求已齐日期。同一当前任务可合并，重新发起时复用已落库结果。历史补数与盘中刷新使用独立状态。
- [x] **净申赎与界面。** 份额记录缺失、停牌、缺价或有来源证实的份额折算影响估算时，显示缺口。长窗口白线在缺口后可按连续区间重新起算，未配齐完整区间时总额留空。页面按需读取，显示实际开始日期、份额和有效估算覆盖、补数进度及失败原因。所选历史区间支持同口径 CSV 导出。
- [x] **验证和交付。** 用少量确定性样本覆盖上市较晚、历史补数、单日缺价以及原有 250 日视图。运行项目测试并在隔离数据库和浏览器检查接口、区间切换和导出。项目经理复核结果，业务部署及在用库历史回填独立于这次本地代码交付。

## 约束

调查时核实的两个交易所最早返回日期作为本项目的回溯下界。实际起点以每只 ETF 的有效记录为准。短窗同步、评分、折溢价历史和看板首屏保持原有开销。长历史请求使用分段和节流，减少单次阻塞，也使中断后可在下次打开该区间时继续。验证优先复用现有测试和一套隔离样本。
