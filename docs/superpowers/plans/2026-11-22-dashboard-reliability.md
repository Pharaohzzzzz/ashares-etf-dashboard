# ETF 资金雷达改进实施计划书

目标。按[接手报告](../../project-review.md)的顺序，把已确认的数据、调度和恢复问题修到本机自用场景可验收，再做轻量的界面和维护改进。项目经理交给一名子 Agent 分批实现并复核结果。

## 第一批 · 数据可信度

1. 在 `server/metrics.js`、`server/service.js` 和行情适配代码统一净申赎计算。按实际交易日检查官方份额连续性，缺同日收盘时估算留空，详情、累计与 CSV 使用同一规则，区分份额与可估算覆盖。核对 `fqt=1` 的影响，估算采用可证明的原始同日收盘，现有复权走势图口径独立保留。
2. 在 `server/db.js`、`server/service.js`、`server/iopv.js` 与 `public/app.js` 对齐来源时间、抓取时间和交易日。较晚抓到的旧报价不得覆盖更新的来源数据。行情、IOPV、份额和评分按各自有效日期输出。首页汇总排除旧日数据，异动按同一评分日和分数排序，休市标识明确。

验收使用同日、缺日、缺价、报价倒退及盘中 IOPV 过期的少量样本，并检查首页、详情和 CSV 的共同口径。

## 第二批 · 无人值守与恢复

3. 在 `server/scheduler.js`、`server/service.js` 与 `server/db.js` 按交易日持久化盘后任务结果，跨分钟可补跑，空结果和实际缺日记为待补，完成槽可重复检查。份额补数分清无标的市场、未上市区间和真实历史缺口，日历源失败时退避。
4. 在 `server/maintenance.js` 改善 Windows 恢复替换和回滚次序，校验通过前保留可回退的原库及必要伴随文件。更新 `README.md` 的实际流程。

验收以跳过盘后分钟仍补跑、部分结果不误报成功、模拟改名失败时旧库仍可读为准。用临时库运行测试。

## 第三批 · 日常效率与维护

5. 用现有运行记录给出数据缺口、来源、归属日期和重试反馈，复用原有 API；按需求补最少的分类型补数操作。让详情的本地数据先呈现，分时单独加载和报错。健康和目录请求避免无关历史读取，保持既有使用方契约。
6. 校准评分零变化、并列、中性样本和至少两只共振，完整 20 日样本才输出 20 日量比。参数变更明确更新版本并补最小口径测试。完善 Windows 构建指纹、工作目录和停服身份识别。
7. 从现行任务列表移除回测残留，保留历史数据。合并同日重复数值和口径文字。`daily_metrics` 的停写以确认实际依赖为前提。添加一条用 Node.js 24 跑现有测试的轻量 CI。前两批打通后，用同一数据日期和规则实现简短盘后摘要。

## 验证和交付

优先使用已有测试，只增加能复现本次实际缺陷的用例。每批覆盖受影响的少量关键路径，整合后运行一次 `npm test`、`git diff --check` 和本机隔离的 HTTP 或浏览器冒烟。改动落在项目本地分支，临时库与在用库隔离。工作区内已有报告继续保留。交付说明包含实际改动、验证结果和仍依赖真实交易时段或外部数据的部分。
