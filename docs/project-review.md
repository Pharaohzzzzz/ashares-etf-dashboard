# ETF 资金雷达项目接手报告

2026-11-22 · `main` · 基线提交 `c835de0` · 接手计划见[计划书](superpowers/plans/2026-11-22-project-takeover.md)

## 项目判断

ETF 资金雷达已经具备本机日常监测所需的功能。首批应修正净申赎口径、首页统计日期、盘后补数和恢复流程。当前工作区的 99 项测试全部通过，但隔离样本复现了跨交易日误算、错过盘后调度和恢复失败后旧库路径消失。后续新增功能应建立在这批修复之上。

## 优先优化

P1 影响数据解释、自动恢复或本地历史可用性。P2 影响日常效率及维护成本，排在 P1 之后。

| 优先级 | 建议与依据 | 验收结果 |
|---|---|---|
| P1 | **统一净申赎口径。** 隔离样本缺少一个交易日官方份额时，详情窗口仍把相隔两天的份额变化乘后一天收盘价。总览的另一条路径会在缺日线时用快照价格。东财日线请求固定 `fqt=1`，用于估算的收盘价需单独核验口径。 [窗口计算](../server/metrics.js#L81) · [总览估算](../server/service.js#L1341) · [日线请求](../server/provider.js#L139) · [现有口径](../README.md#L63) | 同一 ETF 同一交易日的总览、详情和 CSV 使用相同的连续官方份额与同日收盘来源。缺前一交易日份额或同日收盘时保留空值，聚合明确显示完整或部分覆盖。 |
| P1 | **为盘后任务和缺口修复引入可恢复状态。** 假时钟从 15:29 跳到 15:31，再跳到 18:01，两项任务均未触发。启动日线补数也可能漏掉窗口中间的日期，日线返回空数组仍会记成功。`incomplete` 的份额历史缺口没有自动重试。零目标交易所和上市前日期会污染完整性判定。 [调度](../server/scheduler.js#L19) · [日线结果](../server/service.js#L480) · [重试范围](../server/service.js#L842) · [份额同步](../server/service.js#L1000) | 跨过执行分钟、休眠、重启或网络失败后，以交易日和任务补跑，每个成功槽位幂等。空结果或缺失日期保持待补状态，上市前和无监控标的交易所排除在应覆盖日期之外。交易日历失败有退避和可见状态。 |

## 执行路线

1. **数据可信度。** 先修净申赎和跨日期汇总，再校准 IOPV 新鲜度与信号卡选取。交付一组跨日、缺数据和长假验收样本，以 API、页面和 CSV 一致为准。
2. **无人值守可靠性。** 将备份替换安全与盘后补跑分别交付。前者以 Windows 锁定和失败后可恢复为准，后者以日期补齐、无重复、旧库升级和故障重试为准。
3. **日用效率与维护。** 先补浏览器回归与 CI，再做状态展示、目录与详情性能和已确认的退役清理。盘后摘要最后进入排期。

后续收到新目标时，先列计划书，写明目标、范围、步骤和验收标准，再安排一名子 Agent 执行。项目经理复核关键结果并交付。此次接手只新增本报告与计划书。
